VizDOM GPU Runbook

Rent a 24 GB card on Vast.ai, run the lifecycle benchmark sweep, bring one tarball home. About 2 to 3 hours of paid time, 3 to 5 USD.

Kit: deploy/gpu/ on branch develop. Written after the first paid run on 2026-10-25 (RTX 4090); every failure from that day is now caught by setup or preflight. Checkboxes on this page are remembered by your browser.

1. Before renting (once)

  1. Make sure the Vast account has credit. Around 10 USD covers one run. If a card is declined with the Stripe "repeated attempts" message, stop retrying for 24 hours, check that international online payments are enabled in the banking app, or use another funding method.
  2. Create an SSH key and register it with Vast. In PowerShell on the laptop: 
    ssh-keygen -t ed25519 -f $env:USERPROFILE\.ssh\vast_ed25519
Get-Content $env:USERPROFILE\.ssh\vast_ed25519.pub
    Paste the printed line (starts with ssh-ed25519, one line) into Vast → Account → SSH Keys. Do this before launching so the key is injected at boot.
    MobaXterm users: MobaKeyGen's multi-line public-key box is not what Vast wants. Use the one-line form above.

2. Rent the instance

  1. Pick the template first. On the Search page open Templates and choose a PyTorch template with CUDA 12.x (any pytorch/pytorch:*-cuda12.*-devel image). Launch mode: SSH, not Jupyter.
  2. Set the filters.
    GPU
    RTX 4090, A5000 or L4. 1 GPU, 24 GB VRAM. Only if the Aria-UI column is wanted: A100 80 GB or H100 (Aria-UI runs bf16 only, ~50 GB of weights; bitsandbytes skips its experts, so a 48 GB A6000/L40S is not enough either)
    Disk slider
    150 to 200 GB, set before Rent. It cannot grow later; the 16 GB default dies during prefetch
    Host
    Verified, On-demand (not Interruptible), reliability above 99 %
    Internet
    Download at least 500 Mbps
    Max CUDA
    12.1 or higher
  3. Read the Price Breakdown card before clicking Rent. The disk line should read about 0.10 USD/hr, which confirms the slider took. Note the Internet line: at 33 USD/TB the 80 GB download adds about 2.7 USD. Hosts with a lower per-TB price exist.
  4. Click Rent and wait for Running on the Instances page.

3. Connect

  1. Find the SSH port. Open the instance's port list. Use the public IP and the port mapped to 22/tcp, for example 96.241.192.5:42948 → 22/tcp. Ignore 8080 (Jupyter), 6006, 8384, 1111 and the 101xx forwards. The "Machine Copy Port" is not SSH either.
  2. Connect from PowerShell (fastest way to verify the key works): 
    ssh -i $env:USERPROFILE\.ssh\vast_ed25519 -p <PORT> root@<IP>
    Or in MobaXterm: Session → SSH, host, username root, port, then Advanced SSH settings → Use private key → the file without .pub. If it says the key format is unsupported, convert it with MobaKeyGen to .ppk.
    "No supported authentication methods available": the client sent no usable key. Test with the PowerShell line first; if that also fails, the key is not on Vast yet. Add it on the instance's key icon and retry after a few seconds.

4. On the box: the four commands

Everything below runs inside tmux so the sweep survives a dropped Wi-Fi link. Detach with Ctrl-B then D; return with tmux attach -t bench. Ctrl-C works normally inside tmux.

  1. Check the disk you paid for, start tmux, clone. 
    df -h /workspace                      # Avail should be well over 150G
apt-get install -y tmux >/dev/null 2>&1; tmux new -s bench
git clone https://github.com/milanac030988/vizdom.git && cd vizdom
    Expect: the clone is 35 MB and includes the 44 benchmark screens. Nothing needs to be copied from the laptop.
  2. Setup (about 6 minutes). Builds two Python environments because the grounders' own Hub code disagrees on the transformers version. 
    bash deploy/gpu/setup.sh
    Expect two lines near the end like OK /workspace/vizdom/.venv: NVIDIA GeForce RTX 4090, 25 GB VRAM, torch 2.x, transformers 4.49.0 and the same for .venv-legacy with transformers 4.47.1.
    FATAL: N GB free, need ≥ 120 GB: the disk slider was missed. Destroy the instance and re-rent. Nothing else will fit.
  3. Prefetch all models in parallel (10 to 25 minutes, about 80 GB). 
    bash deploy/gpu/prefetch.sh
    Expect: four hf download jobs plus the OmniParser clone, then [patch] util/utils.py: PaddleOCR made lazy, two symlinks in models/omniparser/, a free-disk line, and prefetch done.

    Downloads are resumable: if it ends with FATAL: a download failed, run it again. The "unauthenticated requests" warnings are harmless. If Hugging Face throttles, run hf auth login with a free token and rerun.

  4. Preflight. Do not skip this. It loads every model from the environment the sweep will use, grounds one instruction each, checks the point is inside the image, and checks that ELAM returns a verdict. 
    bash deploy/gpu/preflight.sh
    Expect, all four:
    ui-tars-1.5-7b OK ground -> (x, y) (bf16, ...)
    vizdom-omniparser OK N elements with no "Could not initialize 'omniparser' backend" warning above it
    elam-7b OK ground -> (x, y) ..., judge -> PASSED (or FAILED)
    vizdom-modular OK N elements (the modular backend with the OmniParser YOLO as stage 1)
    aria-ui SKIP GPU has 25 GB; ... needs a >= 70 GB card on a 24 or 48 GB card (OK only on 80 GB). Any other FAIL not available: missing package line is real and must be fixed.
    then preflight passed.

    Any line marked FAIL: fix it before the sweep, do not start the sweep hoping. Paste the FAIL line into the chat; the Troubleshooting table below covers everything seen so far.

  5. Run the sweep and walk away (1 to 2 hours). 
    bash deploy/gpu/run_benchmarks.sh

    It logs itself to sweep.log inside the run folder, prints <column>: OK (Ns) plus the result row after each column, continues past a failed column, writes summary.md with every row, and ends with sweep complete: benchmarks/results/gpu-<stamp>.tar.gz. Detach with Ctrl-B, D.

5. Collect and destroy

  1. Check the summary on the box. 
    cat benchmarks/results/gpu-*/summary.md
ls -la benchmarks/results/
    Expect one row each for vizdom-uied, vizdom-omniparser, vizdom-modular, elam-7b, ui-tars-1.5-7b, aria-ui, and a parity.txt. A column marked FAILED in sweep.log has a .log with the reason; see section 6 to rerun it.
  2. Download the tarball to D:\Project\MasterProject\benchmarks\results\. MobaXterm: SFTP panel on the left, navigate to /workspace/vizdom/benchmarks/results/, right-click the gpu-<stamp>.tar.gz, Download. PowerShell alternative: 
    scp -i $env:USERPROFILE\.ssh\vast_ed25519 -P <PORT> "root@<IP>:~/vizdom/benchmarks/results/gpu-*.tar.gz" D:\Project\MasterProject\benchmarks\results\
tar tzf D:\Project\MasterProject\benchmarks\results\gpu-*.tar.gz | Select-String "summary.md|parity.txt"
  3. Destroy the instance on the Instances page. Stop alone keeps billing for the disk. Only destroy after the previous checkbox.

6. Re-running single columns

After fixing something on the box, rerun only the affected columns into the same run folder. The tarball and summary.md are rebuilt, and nothing earlier is overwritten because every run writes its own timestamped files.

ONLY="elam-7b aria-ui" OUT_DIR=benchmarks/results/gpu-<stamp> bash deploy/gpu/run_benchmarks.sh

Column names: vizdom-uied vizdom-omniparser vizdom-modular elam-7b ui-tars-1.5-7b aria-ui parity. Which environment each column uses is decided by the script: UI-TARS and the VizDOM columns in .venv, ELAM and Aria-UI in .venv-legacy.

Do not chain reruns with one Ctrl-C in mind. On the first run an abort of one manual rerun also stopped the two queued behind it, which is why the ONLY mechanism exists.

7. Back on the laptop

  1. Extract next to the laptop results. 
    cd D:\Project\MasterProject\benchmarks\results
tar xzf gpu-<stamp>.tar.gz
type gpu-<stamp>\summary.md
    The results folder is gitignored by design; keep the tarball as the archive.
  2. Sanity-read each column. A 0.0 row with "all steps errored" in its log is a broken environment, not a measurement. A grounder with many "produced no point" or "no verdict" lines in its log is a prompt-format problem; the first run's ELAM column looked like that.
  3. Publish the numbers in section 6 of benchmarks/README.md, stating the card and date next to them. Scores drift a little between machines (easyocr weights, torch, OpenCV): the 2026-10-25 box gave uied 0.779 / omniparser 0.883 / verify 0.934 where the laptop had 0.803 / 0.916 / 0.957.
